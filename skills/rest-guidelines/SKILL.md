# Zalando RESTful API Guidelines (offline, authoritative)

Every endpoint under `app/api/**` and every path in `docs/openapi.yaml` MUST
comply with the rules below. These are transcribed from the Zalando RESTful API
Guidelines and are self-contained — **do not open or fetch any URL**; apply the
rules here directly. (Origin, for humans only, not to be fetched:
opensource.zalando.com/restful-api-guidelines.)

When you touch an endpoint that violates a rule, reconcile it. The OpenAPI spec
is generated (`scripts/generate-openapi.mjs` → `docs/openapi.yaml`); encode
contract details in the generator, never hand-edit the YAML.

## 1. Naming

- **MUST** use `kebab-case` for path segments: `/api/v1/release-submissions`.
- **MUST** use plural nouns for collection resources; no verbs in paths
  (`/artists`, not `/getArtists`). Non-CRUD actions become sub-resources.
- **MUST** use `snake_case` for all JSON property names and query parameters
  (`artist_id`, `release_date`, `page_size`).
- **MUST** pluralize array field names (`genres`, `items`).
- **SHOULD** suffix timestamps with `_at` (`created_at`, `updated_at`) and dates with `_date`.
- **MUST** keep property names consistent across the whole API surface.

## 2. Resources & URLs

- **MUST** keep URLs free of trailing slashes.
- **MUST** identify resources by stable, opaque IDs (UUIDs), not sequential internal numbers.
- **MUST** avoid actions/RPC in URLs; model state changes as sub-resources or PATCH.
- **SHOULD** limit nesting depth (~3 levels); prefer top-level resources with query filters.

## 3. HTTP methods & idempotency

- **MUST** respect semantics: `GET` safe (no side effects) & idempotent;
  `PUT`/`DELETE` idempotent; `POST` for create / non-idempotent; `PATCH` partial update.
- **MUST NOT** mutate state on `GET` or `HEAD`.
- **MUST** make `PUT` full-replace and `PATCH` partial-merge — don't conflate.
- **SHOULD** support idempotency keys for non-idempotent POSTs that need safe retries.

## 4. Status codes

- **MUST** use only meaningful standard codes:
  - `200` OK, `201` Created (+ `Location`), `202` Accepted, `204` No Content.
  - `400`, `401`, `403`, `404`, `405`, `409`, `410`, `412`, `422`, `429`.
  - `500`, `501`, `503`.
- **MUST** return `201` (not `200`) for successful creation, with the resource location.
- **MUST** return `429` with rate-limit info when throttling.

## 5. Errors — `application/problem+json` (RFC 9457)

- **MUST** return errors as `application/problem+json` with fields:
  `type` (URI), `title`, `status` (int), `detail`, and optionally `instance`.
- **MUST NOT** invent ad-hoc error envelopes.
- **MUST** keep the body `status` equal to the HTTP status.

> **Repo gap:** the shared `withErrorHandler` currently emits `{ "error", "code" }`.
> New/changed endpoints move to problem+json. The spec MUST document whatever the
> endpoint actually returns — never a shape the code doesn't emit.

## 6. Pagination

- **MUST** use cursor-based pagination for large/unbounded collections.
- **MUST** bound page size: a `limit`/`page_size` param with a sane default and
  enforced maximum (repo: default 50, max 200 — `src/lib/partner-api/listParams.ts`).
- **MUST** return the next cursor in the body; the cursor is opaque — never leak
  offset/DB internals.
- **SHOULD** name pagination fields in `snake_case` (target: `next_cursor`).

> **Repo gap:** the current wrapper uses `nextCursor` (camelCase); migrate to `next_cursor`.

## 7. Versioning & compatibility

- **MUST** version the public API in the URL: `/api/v1/*`.
- **MUST** make only additive (backward-compatible) changes within a version;
  never remove, rename, or repurpose an existing field.
- **MUST** introduce breaking changes only via a new version (`/api/v2/…`).
- **SHOULD** ignore unknown request fields (lenient reader) and keep responses forward-compatible.

## 8. Security

- **MUST** authenticate every non-public endpoint; document `401` and `403`.
- **MUST** enforce least privilege via scopes; check the required scope per route.
- Repo: public partner endpoints use the `PartnerApiKey` bearer scheme (`dt_live_…`),
  gated by the `partner_api` org feature + per-key scopes, with tenant isolation on every query.

## 9. Content types & headers

- **MUST** declare every response content type accurately in the spec
  (`application/json`, `text/csv`, `application/problem+json`, …).
- **MUST** default to `application/json`, UTF-8.
- **SHOULD** support `ETag` + `If-None-Match` / `If-Match` for cacheable or concurrency-sensitive resources.

## 10. Data types & formats

- **MUST** use RFC 3339 `date-time` for timestamps and `date` for dates (UTC).
- **MUST** represent enums as lowercase snake_case strings.
- **MUST** expose identifiers as `string` (UUID), not integers.
- **SHOULD** use standardized formats: `email`, `uri`, `uuid`, ISO 4217 currency,
  ISO 3166 country, BCP 47 language.

## Where things live (this repo)

- Routes: `app/api/**/route.ts` (partner API: `app/api/v1/**`).
- Partner-API infra: `src/lib/partner-api/` (`auth.ts`, `scopes.ts`, `listParams.ts`, `queries.ts`).
- Spec generator (source of truth): `scripts/generate-openapi.mjs` — tags,
  `securitySchemes`, `schemas`, per-route `schemaOverrides` declared here.
- Generated spec: `docs/openapi.yaml` (regenerate: `node scripts/generate-openapi.mjs`; never hand-edit).
- Static contract checks: `scripts/verify-api-contracts.mjs` (`npm run verify:api-contracts`).

## Definition of done for any API change

- [ ] Endpoint complies with the MUST rules above (or a documented, tracked gap is called out).
- [ ] `scripts/generate-openapi.mjs` updated so the regenerated `docs/openapi.yaml` reflects the real contract.
- [ ] `node scripts/generate-openapi.mjs` run and the YAML parses.
- [ ] `npm run verify:api-contracts` passes.
